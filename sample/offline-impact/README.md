# Reproducible offline impact demo

Run from the repository root with Python 3.12+ and the project's existing
runtime dependencies already available. No installation or dependency download
is part of this demo. No database, dbt executable, Collibra tenant, credentials,
.env file, configuration file, provider plugin, or network service is required.

PowerShell (source checkout):

```powershell
$env:PYTHONPATH = "src"
python sample/offline-impact/run.py
```

POSIX shell (source checkout):

```sh
PYTHONPATH=src python sample/offline-impact/run.py
```

The command exits 0 and writes only `offline-impact-result.json` in the current
working directory (overwriting that local output on subsequent runs). It uses
the existing dbt loader, downstream impact engine and canonical v1 serializer;
it does not discover installed providers or change CLI behavior. Compare its
bytes with `sample/offline-impact/expected-result.json`, generated by the same
engine. No timestamps or absolute paths enter the result.

## Scenario and evidence

All metadata is synthetic. `changes.json` explicitly selects the table
`offline-demo / demo / analytics / orders`. The hypothetical change is removal
of that table; the engine analyzes the selected identity, not SQL semantics or
an automatic before/after diff. The input does not execute a removal.

`manifest.json` contains four table models and declares these dependencies in
`parent_map` (arrows below show impact propagation):

```text
orders -> order_totals -> revenue_report
inventory (disconnected)
```

- `orders` is the changed root, not a downstream affected asset.
- `order_totals` is directly affected (one reverse `depends_on` hop).
- `revenue_report` is transitively affected (two reverse `depends_on` hops).
- `inventory` is not reached in this fixture; this is not a production safety claim.

The output's `impact.paths` and `affected_edges` expose the dependency steps,
distances and declared dbt provenance (`model.demo.order_totals` and
`model.demo.revenue_report`, version `1.10.0`). `content_identity` and
`graph_identity` provide deterministic hashes. `writes_performed` is 0.
Ancestor identities in `policy_relevant_nodes` are policy matching context,
not additional downstream affected assets.

## Unknowns and boundaries

The manifest declares table dependencies only. Column lineage, actual SQL
breakage, runtime observations, data values, business severity, owners, external
consumers and undeclared dependencies are unknown. There are no policies:
`policy_identity` is null and `affected_policies` is empty; this does not establish
policy compliance. No production or commercial Collibra validation is claimed.
The artifact is evidence of reachability in the supplied graph, not measured
operational impact. Public contracts and Provider SDK API "1" are unchanged.

## Focused verification

```sh
python -m pytest -q tests/test_offline_impact_demo.py
```

The tests deny network/HTTP/database access, compare independent runs byte for
byte against the committed result, verify v1 integrity and exact paths, and
exercise the existing CLI with the built-in registry of a clean environment.
The existing CLI returns 6 when impact is found; this is its expected status.

## Read-only HTML report (Python API)

With `PYTHONPATH=src` set as above, render the validated demo artifact locally:

```python
from pathlib import Path
from governance.impact.html import render_impact_report_from_file

html = render_impact_report_from_file("sample/offline-impact/expected-result.json")
Path("offline-impact-report.html").write_text(html, encoding="utf-8")
```

Open the generated file in a browser. The report is self-contained, has no
JavaScript or external resources, and renders metadata as escaped text, never
as links or markup. No network, credentials, provider discovery or analysis
execution is involved. The Python API returns HTML; the caller explicitly
chooses whether and where to save it. No new CLI command is introduced.

`render_impact_report(result)` accepts an in-memory artifact and checks the
existing v1 schema and content integrity too. Invalid, incompatible or tampered
inputs raise the existing contract exceptions rather than producing a report.
Output is deterministic for the same artifact and does not change its contents.

The report preserves `impacted` or `clear` exactly as recorded. V1 has no coverage
or insufficient-evidence status; missing roots, missing explanation paths and
missing relationship provenance are identified separately when present. A clear
result means no impact identified in the supplied graph, not proof of complete
lineage or production safety. Policies shown are matches, not compliance results.
The renderer neither revalidates graph semantics nor invents missing relationships.
